# ADR 0003: 提供商分类与存储——标签化 + JSON 文件

- 状态: 已接受
- 日期: 2026-09-24

## 背景

由于只抓模型列表（ADR-0002），官方与中转站的取数方式统一为
`{base_url} + key` 调 `/v1/models`。需确定"官方/中转"分类的含义与存储方案。

## 决策

1. **"官方 / 中转"仅为视觉标签**（卡片上的徽章/图标），不影响取数逻辑。
   两类都是：填 base_url + key，调 `/v1/models` 取模型列表。

2. **存储用单个 JSON 文件**：提供商配置 + 抓取到的模型缓存。
   - 不引入数据库。
   - 不记录历史/价格变动。

## 影响

- Provider 数据结构（草案）：
  ```json
  {
    "id": "uuid",
    "name": "My OpenAI",
    "type": "official | relay", // 仅用于展示徽章
    "base_url": "https://api.openai.com/v1",
    "key": "sk-...",
    "models": ["gpt-4o", "..."], // 缓存，抓取后写回
    "last_fetched": "ISO8601"
  }
  ```
- 抓取逻辑对两类 type 完全一致。
- 单文件存储，读写简单；并发写风险低（单用户）。
